# 資料、排程、訓練與推論限制檢查

日期：2026-10-11。檢查範圍包含 `src/diffusiongemma_e4b`、Linux/Windows 啟動腳本、pipeline presets 及測試。

## 已移除或修正

| 位置 | 原本行為 | 現在行為 |
| --- | --- | --- |
| Teacher 輸入 | 依 student prefix 預算保留題目尾端 | 傳送完整保存的 prompt/context，記錄 `teacher_input_policy` |
| 資料來源字數 | 個別欄位及合併題目按字數截短 | 不再截短；保留舊參數以相容現有生成指令與續跑指紋 |
| 資料來源格式 | 換行、縮排與連續空白壓成一格 | 保留內部空白與換行 |
| 對話內容 | 只取前三個 user turns | 不再限制 user turns 數量；第三方 assistant 回答仍不作訓練 target |
| 選項 | 只取前 26 個 | 保留全部選項，26 個之後以數字標示 |
| 來源筆數 | 設定檔中的任意 `max_records` 與 CLI 取較小值 | 僅明確的 CLI 筆數預算限制來源；舊設定檔欄位不再截停來源 |
| 圖片/音訊預取 | 忽略指定值，強制最多兩筆 | 使用指定的 source prefetch 容量；預取存的是處理後 prompt 與媒體路徑 |
| Parquet 預取 | 固定 32 並強制下修批次大小 | `DG_STREAM_PARQUET_BATCH_SIZE` 可設定批次大小，預設 32，不丟資料 |
| Teacher 補位 | 固定 `2 × concurrency` | `DG_TEACHER_OUTSTANDING_MULTIPLIER` 可設定，預設 4；沒有寫死 300 上限 |
| Teacher token 計數 | 完成結果在單一 consumer 計數 | 各 worker 計數，consumer 寫入結果 |
| Teacher 重複回答 | 不同題目得到相同文字也丟掉 | 保留不同題目的相同回答；續跑依 prompt ID 去重 |
| Teacher 回答過濾 | 依詞彙重複率 8% 及 prompt echo 丟棄 | 移除這兩個文字啟發式判定 |
| Teacher 失敗串 | 全域 cooldown 暫停結果處理 | 每個請求自行重試，consumer 不因失敗串睡眠 |
| Teacher 預取 watchdog | 等待資料 900 秒便終止 | 不再按隱藏固定時間終止；來源實際例外仍向外傳遞 |
| Teacher 狀態 | 只見 TPS | 顯示 `http`、`queued`、`done`、`ready`，供對照 vLLM running/waiting |
| Student 文字輸入 | 只保留最後 512/2048 tokens | 保留完整題目與前面回答區塊；prefix length 只作文字 padding 下限 |
| Student 多模態輸入 | processor 截短，之後再次裁切 | processor 不截短，shard 依輸入長度左側補齊；媒體 token types 同步補齊，patch 座標不裁切 |
| Corruption 總筆數 | 生產 preset 固定 block 數，漏用超額回答 | 生產預設 `DG_TARGET_BLOCKS=0`，處理所有回答區塊；明確正值仍是使用者選擇的預算 |
| Corruption 媒體總量 | 累積 64 GiB 後拒絕繼續 | 不因累積媒體位元組數截停資料製作 |
| 配比門檻 | 回答長度或成功率使 share 少一半就中止 | 移除任意 50% 門檻，實際配比仍記錄在報告 |
| Preflight 容量 | 猜測 token/字元換算、來源配額及完整 canvas 利用率，據此拒跑 | 移除不成立的容量判斷；未設定的資料/輸出容量回報為未知 |
| Preflight prefix | 強制至少 512 | 不再要求 512；零 padding 下限可使用 |
| 訓練 warmup | 自動把指定步數截至總 optimizer steps | 使用指定的 warmup，不再自動下修 |
| 推論 temperature | 小值自動改成 `1e-6` | 使用指定值，不做自動替換 |
| 推論 entropy 接受數 | 多餘的 min/max 修正 | 直接使用 sampler 算出的接受數 |
| vLLM 啟動 | 腳本強制 16K context 與 80% GPU 配額 | 僅在對應環境變數明確設定時覆寫 vLLM；可指定 `DG_TEACHER_MAX_NUM_SEQS` |
| 回答終止 | 未保存 finish reason，長度截停也補上 EOT | 新資料保存 `teacher_finish_reason`；已知 `length` 截停的回答不再人工補 EOT |
| Decoder 初始化 | DiffusionGemma 初始化未涵蓋 Gemma4 scalar/buffer | 讓 Gemma4 和 DiffusionGemma 原生初始化都執行，修正實測 NaN |

## 仍有用途的設定

`concurrency` 是呼叫者指定的同時請求數，不是專案硬上限。prefetch、outstanding multiplier、Parquet batch 及 shard bytes 控制工作暫存或分檔，不會裁切樣本內容。

teacher 的 token 目標、明確指定的來源筆數、正值 target blocks、optimizer steps、推論 max-new-tokens 及 denoising steps 是執行預算；CLI 可調。GPU/模型 context、KV cache、canvas=256、原始 Gemma logit softcapping 和 loss/sampler 的數學定義不是額外的資料裁切規則。

HTTP 錯誤、空回答、純 endpoint 錯誤文字、壞 shard、權重缺漏、NaN、跨 train/validation 的 record 洩漏與續跑指紋衝突檢查仍有直接的資料或模型完整性用途。

Smoke preset 保留明確的小型執行預算。設定檔的舊來源 `max_records`、teacher 的舊 prefix/min-tokens/max-chars 與累積 media bytes 參數保留相容入口；已移除的行為不會因此重新生效。

## 既有資料

未重寫、刪除或自動重生既有 teacher JSONL。現有 generation fingerprint 相容邏輯保留，新 metadata 說明完整保存題目政策及伺服器 finish reason。

此次唯讀抽樣快照共 520,327 筆、418,054,571 輸出 tokens。固定種子 reservoir 抽樣 2,000 筆，以本機 tokenizer 重新計數題目並對照 `teacher_input_tokens`：64 筆（3.2%）保存題目比實際送入 teacher 的記錄長；這些樣本占抽樣輸出 tokens 的 4.496%（74,196 / 1,650,234）。

這不是回答錯誤率，也不是所有內容損失的比例。舊來源字數截短、換行壓平、未保存的 finish reason 等資訊不能只靠此比較復原。因此不能宣稱整批已通過內容品質驗證。

新的 corruption 指紋使用 schema 3，避免沿用舊的截短 shards。此修改沒有啟動正式 corruption 或 GPU 訓練。

## 測試取捨

刪除 9 個過時或只綁死實作的測試函式：numpy 自建陣列形狀、三個 preset 常數快照、錯誤的 token/canvas 容量假設、固定音訊啟用政策、已刪除 limiter hook、900 秒 watchdog、全域 cooldown。

移除續跑測試中不再使用的回答文字 hash 斷言，以及無關續跑行為的預設併發/預取數字斷言。修正原本使用 `.json()` mock、根本未測到 SSE length finish reason 的測試。

擴充既有整合測試，確認長 prompt/context 與相同回答均完整保留、完整回答及先前 blocks 可讀回、零 block 預算會處理全部資料、length 截停不人工補 EOT。新增一個多模態 shard 整合測試，驗證內容完整性及 token types/padding/patch 座標對齊。

驗證：107 個測試通過；Linux 腳本語法檢查與 `git diff --check` 通過。測試包含 300 併發補位和小型模型 forward/save/reload/LoRA，不代表已量測正式 GPU/vLLM 吞吐。
